# PagePrd

> 一句话需求 → 一个 HTML 文件。左边点得动，右边对得上号。

写给产品经理的单文件 PRD 工具：把**可点击的高保真原型**和**给研发看的需求说明**焊在同一个 HTML 里，
用功能点编号让两边互相定位。不用 Axure，不用 Figma 导出，不用维护「原型一份、文档一份」然后两边对不上。

- **零依赖**：单个 `.html`，双击就开，断网可用，微信发给研发也能打开
- **零构建**：原生 JS + 内联 SVG 图标，没有 npm、没有打包、没有 CDN
- **可交付**：原型是能直接切图的高保真 UI，不是线框图；说明是研发拿着就能开工的口径

## 效果长什么样

```
┌────────────────────────────────────┬──────────────────────────┐
│  原型（点得动）                     │  需求说明                 │
│ ┌────────┬─────────────────────────┤                          │
│ │ 首页    │ ① 搜索框    ② 分类入口   │  布局说明                 │
│ │ 订单    │ ③ 商家列表              │  交互说明                 │
│ │ 购物车  │ ④ 商品加减              │  页面概述                 │
│ │ 我的    │ ⑤ 底部购物车条          │  功能说明 ③ 商家列表 ←点① │
│ └────────┴─────────────────────────┤  页面级异常               │
│        375 × 812 手机外框           │                          │
└────────────────────────────────────┴──────────────────────────┘
```

- 点原型上的蓝色编号 → 右侧滚到对应卡片并高亮
- 点右侧卡片 → 左侧原型对应元素高亮
- 说明可以直接在页面上改，自动存本机；点「导出 HTML」把改动写回文件
- 「隐藏需求说明」一键收起，原型铺满全屏（用来演示）

## 核心能力

| 能力 | 说明 |
|---|---|
| 左原型 / 右说明双栏 | 菜单驱动切换，同一菜单内从列表点进详情时右侧说明不跳 |
| 功能点编号双向定位 | 一个功能点一个编号，气泡与卡片互跳，避免"这条需求说的是哪个按钮" |
| 页面内直接编辑 | 说明文字就地改，锁定列（功能点名/字段名/字段类型）不可改，防止改出假需求 |
| 自动保存 | `localStorage` 暂存，关掉浏览器再打开还在 |
| 导出 HTML 回合并 | 改完导出，用脚本合并回源文件，**原型区一个字节不动** |
| 导出 Markdown | 给研发/归档用的快照，也可以贴进 Confluence、飞书文档 |
| 四类 PRD 结构 | 布局说明、交互说明（六字段）、前置条件 + 业务流程、两级异常场景 |
| 三种 PC 布局 | 后台 `admin`、官网 `portal`、单卡片 `plain`，按页面真实形态选，不硬套侧边栏 |
| 可交付的图标 | 全套内联 SVG `<symbol>`，跟文字一起变色，研发直接复用 |

## 安装为 Skill

这个仓库本身就是一个 WorkBuddy / Claude Skill 目录。

```bash
git clone https://github.com/woyexiangguolikai/page-prd.git ~/.workbuddy/skills/page-prd
```

Windows 对应路径：`C:\Users\<你>\.workbuddy\skills\page-prd`。目录名必须是 `page-prd`，
`SKILL.md` 要在这一层（不要在子目录里）。装好后新开一个对话即可触发。

**触发方式**：说「给 XX 做个原型」「加个订单管理菜单」「我改好了帮我合并」「导出成 Markdown」，
或者直接给一段需求描述。

## 三种用法

### 1. 让 AI 生成

```
给校园外卖小程序做一版原型，要首页、订单、购物车、我的四个 tab
```

AI 会选模板 → 复制成 `prototypes/<系统名>/index-mobile.html` → 改原型和说明 → 跑校验。

### 2. 手动改说明

双击打开 HTML → 点「编辑需求说明」→ 直接改 → 点「导出 HTML」下载新文件 → 让 AI 合并回去：

```bash
node scripts/merge-spec.mjs 下载的.html 原文件.html
```

合并脚本按 JSON 路径逐字段比对，只写回改动项，自动备份原文件为 `.bak.html`，并打印变更清单。

### 3. 只导出文档

```bash
node scripts/export-md.mjs prototypes/某系统/index-web.html
```

生成同目录快照 `<系统名>-需求说明-<时间戳>.md`，含布局说明、交互面板、前置条件、业务流程、
字段表、异常场景。原型和说明文件都不改动。

## 数据模型

右侧说明完全由 `#prd-data` 里的 JSON 驱动，**不要手写渲染后的 DOM**——下次渲染会被覆盖。

### 章节类型

| type | 用途 | 渲染形态 | 位置 |
|---|---|---|---|
| `layout` | 布局说明 | 键值列表（页面顶部 / 主体 / 空状态 / 底部 / 刷新机制） | 恒定第一 |
| `interactions` | 交互说明 | 每个面板一张卡，六字段 | 第二 |
| `overview` | 页面概述 | 段落 / 键值 / 列表 / 表格 | 中段 |
| `permission` | 权限说明 | 四列表（功能点🔒 / 操作权限 / 数据权限 / 备注） | 中段 |
| `features` | 功能说明 | 每个功能点一张卡，带编号 | 中段 |
| `exceptions` | 页面级异常 | 三字段卡片 | 恒定最后 |
| `custom` | 自定义 | 同 overview，可整块删除 | 中段 |

### 功能点的字段

```jsonc
{
  "fp": 7,                       // 编号，同一菜单内唯一，不跳号
  "name": "订单卡片",             // 🔒 锁定
  "desc": "展示订单号、状态、商品摘要、金额与快捷操作。",
  "precondition": "已登录；订单接口已返回首屏数据",   // 可选
  "flow": [                      // 可选，竖向时间线
    { "t": "进入订单 tab", "type": "start" },
    { "t": "点击卡片主体？", "type": "branch", "note": "是 → 进详情；否 → 停留" },
    { "t": "加载下一页", "type": "end" }
  ],
  "fields": { "table": "list", "rows": [] },        // 可选，字段表
  "rules": ["倒计时归零自动刷新为「已取消」"],        // 可选
  "exceptions": [                // 可选，只写这个功能点自己的异常
    { "scene": "支付超时", "behavior": "订单自动关闭", "message": "「订单已超时关闭，请重新下单」" }
  ],
  "states": ["待付款", "待取餐", "已完成"]           // 可选
}
```

### 异常场景分两级

| 级别 | 写在哪 | 写什么 | 判断口径 |
|---|---|---|---|
| 功能点级 | `features.items[].exceptions` | 校验不通过、状态冲突、单接口失败 | **换掉这个功能点，这条异常还在吗？** 不在就挂这里 |
| 页面级 | 独立 `exceptions` 章节 | 断网、无权限、整页加载失败、强制更新 | 还在 → 放页面级 |

页面级异常渲染在说明最后，标题下会带一行分工说明；功能点级的渲染在功能点卡片内部，
跟着 `fp` 编号走——研发领哪个功能点，异常就在那一张卡里。

## 脚本

三个 Node 脚本，无第三方依赖（Node 18+）：

```bash
node scripts/validate.mjs    <index.html>                 # 交付前自检，退出码 1 = 有必须修的错误
node scripts/export-md.mjs   <index.html> [输出.md]        # 导出 Markdown 快照
node scripts/merge-spec.mjs  <导出.html> <目标.html>       # 合并浏览器里的改动
```

`merge-spec.mjs` 支持 `--dry-run`（只看差异不写）、`--no-backup`（不生成 .bak）。

### validate 查什么

| 检查 | 级别 |
|---|---|
| 数据块是合法 JSON | 错误 |
| 每个菜单都有对应原型页面 | 错误 |
| 布局说明缺失 / 没有内容行 | 错误 |
| 每个菜单都要有交互说明，六字段齐全 | 错误 / 警告 |
| 异常场景三字段齐全（两级都查） | 错误 / 警告 |
| 业务流程节点没写文字 | 错误 |
| 编号双向核对：左边有 `data-fp=3` 右边必须有功能点 3，反之亦然 | 错误 |
| 部分页面有交互说明/异常场景、部分空着 | 警告并列名 |
| 异常总数 < 3 条，或页面级为 0 | 警告 |

## 几个刻意的取舍

**右侧 430px 放不下横向流程图，所以业务流程用竖向时间线。** 横向 4 个节点就折成乱码；
竖排用 `start / step / branch / end` 四种节点表达分支，窄栏里也读得清楚。

**编号气泡放右上角并自动避让裁切。** 第一版放左上角，直接盖住按钮文字。现在渲染后会实测元素到
容器四边的距离，右侧放不下翻到左侧、上方放不下翻到下方、两边都不够才收进内侧。

**图片位用固定尺寸容器 + 矢量图标，不内嵌 base64 照片。** 一张 800×400 的 JPEG 转 base64 约
100–150KB，几张就让文件翻倍，而且研发拿到没法替换。现在换 `<img src="./assets/shop-01.jpg">` 即可，
样式一行不用改。

**说明用 JSON 驱动，不直接改 DOM。** 手改 DOM 会在下次渲染时被覆盖，"编辑 → 导出 → 合并"这条链路
就没法保证干净。

**合并脚本按路径比对，不按文本 diff。** 只写回真正改动的字段，原型区 HTML 不参与合并，
避免"合并一次原型就变形"。

## 已知限制

- **单文件不适合超大系统**：一个菜单 8~12 个功能点是舒适区，超过 20 个建议拆文件
- **不做交互逻辑验收**：原型只表达"长什么样、怎么跳"，真实业务逻辑仍要靠接口和测试
- **移动端不校验控件覆盖率**：大量点击区域由 `div` 承载，只做编号双向核对
- **编辑后的数据存 localStorage**：换浏览器、清缓存会丢，改完记得先「导出 HTML」
